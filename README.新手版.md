# Logic 文件工具包 · 新手版（零基础）

> **这份文件给谁看**：只用过 Logic、不懂代码、也不想懂代码的音乐人。
> 全文没有一行需要你亲手敲的命令——所有事情都是「你把一句话发给 AI」。
>
> 想自己看代码/字节那一层：去看同目录的 `README.md`。
> 想接着开发这个项目：去看 `HANDOFF.md`。

---

## 一、先说清楚：这东西到底解决什么问题

Logic 里有一类活儿，**不难，但特别费手**：同样的动作重复几十遍、上百遍。

这个工具包就是为这类活儿做的。三个真实例子：

| 你原来要做的 | 现在要做的 |
|---|---|
| 60 条鼓/贝斯/吉他轨道，每条照着同一套路点插件、调参数，一条 3–5 分钟 | 把清单写成一段话，AI 一次生成 60 个预设文件 |
| 想从零开一个干净的 4 轨工程、定 96 BPM、起个名字 | 说一句话，AI 给你一个能直接打开的 `.logicx` |
| 第 3 小节要变 7/8、第 11 小节要变 6/4 | 说一句话，AI 写进工程文件 |

**它不是 Logic 的替代品，也不是插件。** 它是一套「说明书 + 工具 + 模板」，
让 AI 能直接读写 Logic 的文件；你负责说要什么、回 Logic 里看一眼。

## 二、先认识三个词（30 秒）

| 词 | 人话 |
|---|---|
| **工程**（`.logicx`） | 你的歌。在 Finder 里它长得像一个文件，其实是**一个文件夹**，Logic 的全部内容都在里面 |
| **预设**（`.patch` / `.cst`） | 一条通道条的存档：插件顺序 + 参数 + 名字。下次能直接调出来 |
| **这个包** | 别人已经替你踩完坑写下的说明书，加上能干活的代码和现成模板 |

## 四、15 分钟上手（4 步，每步一句话）

### 第 1 步：把仓库放到电脑上

复制这段发给 AI：

```
请帮我把这个仓库克隆到 ~/logic-format-kit ：
<这里粘贴 GitHub 地址>

如果没装 git，先告诉我要怎么装，不要自己乱装东西。
```

### 第 2 步：让 AI 自检（确认环境没坏）

```
请进入 ~/logic-format-kit ，运行：
python3 selftest_all.py

把最后三行输出原样贴给我。如果最后一行不是 all modules ok，把完整报错贴给我。
```

看到 `all modules ok` 就可以往下走；看不到就把报错整段发给 AI，别自己猜。

### 第 3 步：告诉 AI 你要什么

去下面**第六节**，挑一个跟你需求最像的 Prompt，改掉里面的名字和小节号，发过去。

### 第 4 步：回 Logic 里检查（这一步不能省）

AI 干完会说「改好了」。**不要信这句话，去看文件**：

1. 在 Logic 里打开它
2. 只看三件事：**名字对不对、数值对不对、旁边的东西有没有被弄坏**
3. 没问题就 ⌘S 保存；有问题就让 AI 重来（你让它先备份过，原文件还在）

> 为什么必须看：Logic 遇到写坏的文件**经常不报错**，只是静默地少一条轨、少一个标记。
> 所以「AI 说成功」和「真的成功」是两件事——第六节每个 Prompt 都要求它**把实际读回来的数值列给你**，
> 你对着那串数字核对，比看它说「已完成」可靠得多。

## 五、现在能做什么、不能做什么

### ✅ 已经做过、并在 Logic 里实测通过的

| # | 能力 | 你在 Prompt 里怎么说 |
|---|---|---|
| 1 | 批量生成通道条预设 | 「按这个清单做 20 个预设」 |
| 2 | 改已有预设里的插件参数 | 「把 Kick In 里的 Pro-C 3 阈值改成 -22dB」 |
| 3 | 复制 / 改名 / 调整预设 | 「复制一份叫 Kick Out，把 EQ 挪到压缩器前面」 |
| 4 | 改拍号（含中途变拍） | 「第 3 小节 7/8，第 11 小节 6/4」 |
| 5 | 改调号（含中途变调） | 「第 4 小节 E♭ 大调，第 8 小节升 F 小调」 |
| 6 | 和弦轨批量写和弦 | 「第 1 小节 C，第 2 小节 Am7，第 6 小节 C7(9,♯11,♭13)」 |
| 7 | **从零建工程**（1–4 轨 + 改名 + 定速） | 「建一个 4 轨、96 BPM、叫 Demo 的工程」 |
| 8 | 新建 / 删除音频轨（含删中间那条） | 「加两轨音频」/「删掉第 2 条」 |
| 9 | 推子 / 声像 / 静音 / 独奏 / 输出路由 | 「把 Bass 压到 -9dB，声像往左 20」 |
| 10 | 移动 / 复制 MIDI 区域 | 「把第 3 小节的区域挪到第 9 小节」 |
| 11 | 插入插件、做 Summing / Folder Stack | 「这 5 轨打个 Summing Stack 叫 Drums」 |
| 12 | 检查文件有没有写坏 | 「先检查这个文件结构对不对，再动手」 |

### 🟡 现在**不能**做的（或者只能做一半）

| 做不到 | 现在能到什么程度 | 替代办法 |
|---|---|---|
| **新建 Marker**（标记点） | 读、移动、改名、删除都可以；**新建不行** | 在 Logic 里按一下加标记，剩下的交给 AI |
| **新建 Send**（发送） | 改已有 Send 的电平和目的地可以；新建不行 | 在 Logic 里点一个 Send，再让 AI 调电平 |
| Polyverse（Filterverse/Wider）、Slate Digital 这两个厂的插件参数 | 能认出是什么、但**拒绝盲写**（怕写坏） | 在 Logic 里手动调，或用 Logician 遥控 |
| 从零建**超过 4 轨**的工程 | 1–4 轨可靠；再多会丢轨 | 先建 4 轨，剩下的在 Logic 里按 ⌘⇧N 加（很快） |
| 真删和弦记录 | 删不掉，Logic 会保留记录 | 用「No Chord」空和弦代替 |

> 上面每一条「做不到」都不是偷懒：每一条都在 `docs/08-roadmap.md` 里写了
> 卡在哪、需要什么条件才能做，谁想接着做可以照着往下推。

## 六、可以直接抄的 Prompt

> 用法：整段复制，把 `<尖括号>` 里的东西换成你自己的，发给 AI。
> **每一段都已经写好了三条保护**：先备份、先输出到桌面给你看、改完把实际数值列出来。
> 别删这三条——它们是拿真实事故换来的。

### 0）通用开场（第一次用，或换了一个新 AI）

```
我给你一个项目：Logic 文件工具包（logic-format-kit），已经在 ~/logic-format-kit 。

它让 AI 能直接读写 Logic 的工程文件（.logicx）和通道条预设（.patch / .cst）。

请按顺序做：
1. 读 ~/logic-format-kit/CORE.md（这是核心，优先于其它文件）。
2. 跑一遍自检：cd ~/logic-format-kit && python3 selftest_all.py
3. 用三句人话告诉我：
   - 现在能做什么
   - 现在不能做什么
   - 你建议我先做哪件事
4. 然后等我告诉你我要做什么。

必须遵守：
- 改任何文件之前先备份（旁边复制一份 .backup）。
- 不要手搓文件结构，一律「拿 templates/ 里的模板改」。
- 改完不要只说"成功"，要把文件里**实际读回来的数值**列给我。
- 同一件事失败三次就停下来告诉我，不要继续猜。
- 不确定就说"不确定"，不要假装成功——Logic 不会报错，只会静默失效。
```

### 1）批量做通道条预设

```
请帮我批量生成 Logic 通道条预设，用 ~/logic-format-kit/templates/patch/ 里的模板当母版。

要做这两条：

1) 名字 "Kick In"
   插件顺序：Gain → Pro-Q 4 → SPL Transient Designer → Pro-C 3 → bx_meter
   参数：Pro-Q 4 高通 30Hz、350Hz 减 2dB；Pro-C 3 阈值 -18dB、比例 2:1

2) 名字 "Snare Top"
   插件顺序：Gain → Pro-Q 4 → Pro-C 3 → bx_meter
   参数：Pro-Q 4 高通 80Hz、200Hz 减 3dB；Pro-C 3 阈值 -15dB、比例 3:1

要求：
- 生成到 ~/Desktop/我的新预设/ 下面，先不要写进我的 Logic 预设库
- 生成完，把每个文件里读回来的「名字 + 插件顺序 + 关键参数」列成表给我核对
- 最后告诉我这些文件要怎么导入 Logic
```

> 需要做 60 条？把清单写全，或者写成「鼓组 12 条、贝斯 6 条，都按上面这套参数，名字我列在下面」。
> **第一次先让它做 2 条**，你在 Logic 里试过没问题，再一次做 60 条。

### 2）改已有预设里的插件参数

```
这是我要改的预设：
~/Music/Audio Music Apps/Patches/Audio/Kick In.patch

请把它里面的 Pro-C 3 改成：阈值 -22dB、比例 6:1、启动 3ms。
改之前先备份成 Kick In.backup.patch。
改完把**实际读回来的**数值列给我，不要只说"成功了"。
```

### 3）复制一个预设并调整

```
请把 ~/Music/Audio Music Apps/Patches/Audio/Kick In.patch 复制一份，
新名字叫 "Kick Out"，并把 SPL Transient Designer 挪到 Pro-Q 4 前面。
放到 ~/Desktop/ 下面给我检查，不要动原来那个。
```

### 4）改拍号（含中途变拍）

```
我的工程：~/Music/Logic/我的歌.logicx

请帮我改拍号：
- 第 1 小节保持 4/4
- 第 3 小节改成 7/8
- 第 11 小节改成 6/4
- 其它小节不要动

改之前把整个 .logicx 文件夹备份一份（叫 我的歌.backup.logicx）。
改完把实际写进去的数值列出来给我：位置 / 分子 / 分母。
```

> **如果这个工程里目前一个拍号变化都没有**：先在 Logic 里随便加两个（比如第 2 小节 3/4、
> 第 4 小节改回 4/4，存盘）。这两条就是「占位格」——工具是**改已有的事件**，不是凭空插入。
> 也可以让 AI 直接用模板新建一个干净工程（自带 4 个格）。

### 5）改调号 + 写和弦（顺序很重要）

```
我的工程：~/Music/Logic/我的歌.logicx

1. 先改调号：
   - 第 4 小节 E♭ 大调（三个降号）
   - 第 8 小节升 F 小调（三个升号）
2. 再写和弦（一定要在调号之后）：
   - 第 4 小节：E♭
   - 第 5 小节：B♭7
   - 第 6 小节：C7(9,♯11,♭13)
   - 第 7 小节：无和弦

改之前备份整个 .logicx。
改完把每个位置的实际调号 / 和弦名读出来列给我。
```

> 「先调号再和弦」不是客套话：Logic 在改调号时可能把和弦一起移调，顺序反了结果就错。

### 6）从零建一个干净工程

```
请在 ~/Desktop/ 下建一个新的 Logic 工程：Demo.logicx

要求：
- 4 条音频轨
- 96 BPM
- 4/4 拍
- 工程名叫 Demo

用 ~/logic-format-kit 里的 create_project()（在 logicfmt/project.py）做，不要手搓字节。
建完告诉我：文件在哪、几条轨、多少 BPM。
我会在 Logic 里打开验证；如果打不开或者轨数不对，直接告诉我，不要假装成功。
```

> 只要 1–4 轨是可靠的。要更多轨：先建 4 轨，打开 Logic 里按 ⌘⇧N 加剩下的，很快。

### 7）新建 / 删除音频轨、调推子

```
我的工程：~/Music/Logic/我的歌.logicx

请做两件事：
1. 删掉第 2 条音频轨（现在叫 "Audio 2"），其它轨保持原样、不要重新编号
2. 把剩下的 "Audio 3" 改名叫 "Bass"，推子压到 -9 dB，声像往左 20

改之前备份整个 .logicx。
用 logicfmt/project.py 的 remove_audio_track() / rename_channel()、logicfmt/mixer.py 的
set_volume() / set_pan()，不要手搓字节。
改完把读回来的轨道清单（第几条 / 名字 / 音量 / 声像）列给我。
```

### 8）移动 / 复制 MIDI 区域

```
我的工程：~/Music/Logic/我的歌.logicx

请把 "Inst 1" 这轨第 2 个区域（现在在第 3 小节）挪到第 9 小节，
再把它复制一份到第 17 小节，副本名字叫 "COPY-A"。

改之前备份整个 .logicx。
改完把每个区域的名字和所在小节列出来给我。
```

### 9）先检查、再动手

```
请先检查这个文件的结构有没有问题，暂时不要改：
~/Desktop/我的新预设/Kick In.patch

告诉我：
1. 结构是否完整
2. 里面有几个插件、分别是什么、什么顺序
3. 名字对不对
4. 有没有两个一模一样的身份编号（这会让 Logic 认错文件）
```

## 七、五条安全提醒（请认真看）

1. **改之前一定备份。** 最稳的做法：自己先在 Finder 里把文件复制一份到桌面。
2. **一次只改一处。** 第一次先改一个值、回 Logic 看一眼，确认没问题再加量。
3. **AI 说「成功」不等于成功。** 要它把改完的**实际数值**列出来，你核对。
4. **别拿唯一的工程做试验。** 拿副本试，确认了再换到正式的那份。
5. **版本要对上。** 这套东西是在 **Logic 12.4** 上实测的。你的版本不同，就先让它跑自检 +
   拿模板做一个小改动，确认没问题再上量。

## 八、出问题了怎么办

把**现象**（不是你的猜测）发给 AI：

```
出问题了。

现象：<比如：Logic 打开说 This is not a Logic Pro project；或者轨数少了 1 条；
或者第 3 小节的拍号没变；或者 Logic 完全没报错但就是没生效>

请读 ~/logic-format-kit/docs/06-failure-modes.md ，对着症状找原因，
然后告诉我：是哪一个原因、怎么修、以及我需要手动做什么。
不要直接改我的文件，先说方案。
```

如果它想不出原因，让它读 `docs/08-roadmap.md`——很多「奇怪现象」其实是已知的边界
（比如新建 Marker、新建 Send 目前就是做不到）。
