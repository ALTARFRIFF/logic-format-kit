# Logic 文件工具包 · 新手版

> 这份是给「只会用 Logic、刚装好 AI Agent」的人看的。不用懂任何代码。
> 全文只有中文。想深入看技术细节，去看同目录的 `README.md`。

---

## 先说一句话：这东西是干什么的

它是一套**资料 + 工具**，让 AI 能直接读写 Logic 的工程文件和通道条预设文件。

翻译成音乐人的话：

> **Logic 里那些需要你一遍遍点的重复劳动，可以让 AI 一次做完。**

比如「按同一个套路给 60 条轨道做通道条预设」「在工程第 3 小节变 7/8、第 11 小节变 6/4」——这些在 Logic 里只能手点，现在可以写句话让 AI 干。

# 一、新手上手指南

## 第 0 步：你需要什么

| 东西 | 说明 |
|---|---|
| 一台 Mac | 跟 Logic 同一台 |
| Logic Pro | 用来最后检查成果 |
| 一个 AI Agent | 能读写你电脑上的文件的都行（Claude Code、Cursor、DeepSeek Harness 之类） |
| 这个仓库 | 下面第 1 步会拿 |

**不需要**：不需要会写代码，不需要装 Python（Mac 自带），不需要懂什么"字节""偏移"。

## 第 1 步：把仓库放到电脑上

把这句话发给你的 AI：

```
请帮我把 https://github.com/<仓库地址> 克隆到 ~/logic-format-kit
如果 git 没装，告诉我怎么装。
```

装好之后，你的电脑上会有这么一个文件夹：

```
~/logic-format-kit/
├── README.md          ← 技术版说明，你暂时不用看
├── CORE.md            ← 给 AI 看的说明书，你也不用看
├── docs/              ← 详细的格式资料
├── logicfmt/          ← 真正干活的代码
└── templates/         ← ★ 模板文件，AI 干活要用它
```

## 第 2 步：先让 AI 做个自检

把这句话发给 AI：

```
请进入 ~/logic-format-kit，运行这两个自检，把结果告诉我：
python3 logicfmt/chord.py
python3 logicfmt/meterkey.py
两个都打印 OK 就说明环境没问题。
```

**看到两个 OK，就可以开始了。** 没看到就把报错原文发给 AI。

## 第 3 步：告诉 AI 你要什么

用下面**第三部分**里现成的 Prompt，改一改文件路径就行。

## 第 4 步：回 Logic 检查

AI 改完会告诉你改了什么。你要做的：

1. 在 Logic 里打开那个文件
2. 看三件事：**名字对不对、值对不对、旁边的东西有没有被弄坏**
3. 没问题就保存；有问题就让它重来（AI 改之前会备份）

## 第 5 步：出问题了怎么办

把这句话发给 AI：

```
出问题了。<具体现象>
请读 ~/logic-format-kit/docs/06-failure-modes.md，对着症状找原因，然后告诉我怎么办。
```

# 二、这个包能帮你做什么

## ✅ 已经能做的

### 1. 批量做通道条预设（Patch）

一次做好几十上百条，每条的名字、插件顺序、插件参数都按你的要求设好，直接能用。

> 原来：一条条点，一条 3–5 分钟。
> 现在：写一段话，一次一批。

### 2. 改插件里的参数

比如「把这一轨的 Pro-C 3 阈值改成 -20dB、比例 4:1」。压缩器、EQ、饱和器这些都能改。

### 3. 复制 / 改名 / 换插件顺序

已有的 patch 想换个名字、加一个插件、把 EQ 挪到压缩器前面——这些都能做。

### 4. 在工程里改拍号（包括中途变拍）

第 3 小节变 7/8、第 11 小节变 6/4、中间再变 2/2——都能写进去。

### 5. 在工程里改调号（包括中途变调）

第 4 小节增三和弦的 E♭、第 8 小节升 F 小调——大小调、升降号方向、连「Disable ♭♯」（决定写成 B♭ 还是 A♯）都能控。

### 6. 在和弦轨上批量写和弦

C、Am7、F♯m7♭5、B♭7、E♭/G、C7(9,♯11,♭13)——包括多扩展音叠加和斜杠低音。

### 7. 检查一个文件有没有写坏

不用打开 Logic，先做结构检查，提前发现问题。

## ⚠️ 现在还不能做的（需要别的办法）

| 做不到 | 怎么办 |
|---|---|
| 新建轨道 / AUX / Stack、改路由、改推子音量 | Logic 的这部分结构还没解开。用 **Logician**（一个能遥控 Logic 的 AI 工具），或者手动 |
| Waves 插件的参数 | 它的格式没解开。用 Logician 遥控 Logic 改，或者手动 |
| 从零造一个 Logic 工程 | 不建议。一律"拿模板改" |
| 删除和弦 / 事件 | 用「空事件」代替，不是真删 |

## 功能 1：批量做通道条预设

**需要**：仓库 + `templates/patch/` 里的模板
**要不要 Logic**：检查的时候要

```
我克隆了 logic-format-kit 到 ~/logic-format-kit。
请先读 ~/logic-format-kit/README.md 和 CORE.md，再帮我批量生成 Logic 通道条预设。

我要做这 3 条：

1) 名字叫 "Kick In"
   插件顺序：Gain → Pro-Q 4 → SPL Transient Designer → Pro-C 3 → bx_meter
   参数：Pro-Q 4 高通 30Hz；350Hz 减 2dB；Pro-C 3 阈值 -18dB、比例 2:1

2) 名字叫 "Snare Top"
   插件顺序：Gain → Pro-Q 4 → Pro-C 3 → bx_meter
   参数：Pro-Q 4 高通 80Hz；200Hz 减 3dB；Pro-C 3 阈值 -15dB、比例 3:1

3) 名字叫 "Bass DI"
   插件顺序：Gain → Pro-Q 4 → Pro-C 3 → bx_meter
   参数：Pro-Q 4 高通 35Hz；600Hz 减 2dB；Pro-C 3 阈值 -20dB、比例 4:1

要求：
- 用 ~/logic-format-kit/templates/patch/_TEMPLATE-A.patch 当母版
- 生成到 ~/Desktop/我的新预设/ 下面，先不要写进我的 Logic 预设库
- 每一步做了什么都告诉我，最后列一个清单给我核对
```

## 功能 2：改已有 patch 里的插件参数

**需要**：仓库 + 那个 patch 文件
**要不要 Logic**：检查的时候要

```
这是我要改的 patch 文件：
~/Music/Audio Music Apps/Patches/Audio/Kick In.patch

请把它里面的 Pro-C 3 改成：阈值 -22dB、比例 6:1、启动 3ms。
改之前先把原文件备份成 Kick In.backup.patch。
改完把实际读回来的数值列给我看，不要只告诉我"成功了"。
```

> 最后那句话很重要。以前出现过"AI 说成功了、文件其实一点没变"的情况。

```
新名字叫 "Kick Out"，并且把 SPL Transient Designer 挪到 Pro-Q 4 前面。
放到 ~/Desktop/ 下面给我检查，不要动原来那个。
```

## 功能 4：在工程里改拍号

**需要**：仓库 + 一个已经装了"拍号变化"的工程文件
**要不要 Logic**：要（原因见下面的说明）

**先说清楚一件事**：这个工具是"改已有的事件"，不是"凭空插入新事件"。
所以如果你的工程里**目前一个拍号变化都没有**，先花 20 秒做一件事：

> 在 Logic 里随便点两次拍号变化（比如第 2 小节设 3/4、第 4 小节设回 4/4），保存。
> 这两条就是"占位格"。AI 会把它们改成你真正想要的。

如果你不想动自己的工程，也可以让 AI **从模板新建一个干净工程**（自带 4 个拍号格）。

```
我的工程在这里：~/Music/Logic/我的歌.logicx

请帮我改拍号：
- 第 3 小节改成 7/8
- 第 11 小节改成 6/4
- 第 1 小节保持 4/4
- 其它小节不要动

改之前先备份整个 .logicx 文件夹。
改完把你写进文件的实际数值列出来（位置 / 分子 / 分母），我要核对。
```

---

## 功能 5：在工程里改调号

**需要**：同功能 4（先有占位事件，或者从模板新建）

```
我的工程在这里：~/Music/Logic/我的歌.logicx

请帮我改调号：
- 第 4 小节改成 E♭ 大调（三个降号）
- 第 8 小节改成升 F 小调（三个升号）
- 第 12 小节改成 B♭ 大调，并且勾上 "Disable ♭♯"（这样会显示成 B♭ 而不是 A♯）

注意：先写调号，再写和弦——顺序反了和弦会被移调。
改之前备份整个 .logicx。
```

> 「先写调号再写和弦」不是废话：Logic 有"改调号时是否连和弦一起变调"的行为，顺序错了结果会错。

## 功能 6：在和弦轨上批量写和弦

**需要**：仓库 + `templates/logicx/_CHORD.logicx`（自带 15 个格）

```
用 ~/logic-format-kit/templates/logicx/_CHORD.logicx 当底稿，
生成一个新工程到 ~/Desktop/我的和弦工程.logicx，和弦这样排：

第 1 小节：C
第 2 小节：Am7
第 3 小节：F♯m7♭5
第 4 小节：B♭7
第 5 小节：E♭/G      （低音是 G）
第 6 小节：C7(9,♯11,♭13)
第 7 小节：无和弦
第 8–15 小节：也全部设成无和弦（把模板里剩下的格子清空）

每个和弦占满一小节。
生成后把每个位置的实际和弦名字列给我核对。
```

## 功能 7：检查一个文件有没有写坏

**需要**：仓库 + 要检查的文件

```
请检查这个文件的结构有没有问题：
```

# 四、直接把整个项目丢给 AI 的通用 Prompt

复制下面这一整段，发给 AI。它会自己去读资料、自检、然后问你想要什么。

```
我给你一个项目：Logic 文件工具包（logic-format-kit）。

它是一套「让 AI 能直接读写 Logic Pro 的工程文件（.logicx）和通道条预设（.patch / .cst）」的
资料 + 参考实现。里面包含：
- CORE.md：给 AI 看的决策树和铁律
- docs/01~06：各类文件的格式细节、验证方法、失败模式
- logicfmt/：可以运行的 Python 代码
- templates/：现成的模板文件（不用自己造）

请你按下面顺序做：

1. 如果还没克隆，先把仓库克隆到 ~/logic-format-kit。仓库地址是 <粘贴地址>。
2. 通读 ~/logic-format-kit/CORE.md。这是核心，优先于其它文件。
3. 运行自检，确认环境可用：
   cd ~/logic-format-kit && python3 logicfmt/chord.py && python3 logicfmt/meterkey.py
4. 简要回答我三件事：
   - 这个包现在能做什么、不能做什么（用一句人话各说一条）
   - 有哪些地方是「未验证」的（CORE.md 第 6 节列了清单）
   - 接下来你建议我先做哪件事
5. 然后等我告诉你我要做什么。

几条必须遵守的规矩（这些是这套资料的作者用真实事故换来的）：
- 永远先备份，再改文件。改完不要用「已完成」当结论，要给出实际读回来的数值。
- 不要手搓文件结构。一律「拿 templates/ 里的模板改」。
- 如果一件事要连续失败三次，停下来告诉我，不要继续猜。
- 结果不确定的时候，宁可说"不确定"，也不要假装成功——Logic 不会报错，只会静默失效。

现在开始第 1 步。
```

# 五、几条安全提醒（请认真看）

1. **改之前一定备份。** 每次让 AI 动手前，先自己复制一份原文件到桌面。
2. **不要一次改一大堆。** 第一次先改一处、回 Logic 看一眼，确认没问题再加量。
3. **AI 说"成功"不等于成功。** 让它把改完的实际数值列出来，你核对。
4. **别拿唯一的工程文件试验。** 拿副本试，确认了再换到正式的。
5. **版本要对上。** 这套资料是在 Logic 12.4 上测的。你的版本不同的话，先让 AI 跑一遍自检，并用模板试一个小改动，确认没问题再用。
