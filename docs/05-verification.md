# 附录 05 —— 验证：怎么确认你真的改成功了

> 这份资料里最贵的教训都在这一页。**逻辑满分、报告全绿、文件没变**这件事真的发生过。

---

## 1. 为什么必须验证

Logic **不给你错误信息**。三种失败表现得完全一样：

| 你做的 | 失败时你看到 |
|---|---|
| 写错一个字节 | Logic 打开时"文件已损坏"或直接打不开 |
| 写错一个长度字段 | 打开了，但某些对象消失 |
| 写了一个 Logic 不接受的值 | 打开正常，值被**自动改回默认** |
| 写了一个它不认识的结构 | **什么都不发生**，值就是你写的那样，但 Logic 不用它 |

最后一行是最危险的：**文件真的变了、值真的写进去了、Logic 就是不认。**

---

## 2. 三个独立见证（至少用两个）

| 见证 | 做法 | 能证明什么 |
|---|---|---|
| **字节级** | `md5` 变化 + `cmp -l` 计数差异字节 + 断言差异数 == 预期 | 文件真的改了，且只改了该改的地方 |
| **解析级** | 用同一个解析器**重新读**文件，读出目标值 | 你的写入路径与读取路径一致 |
| **宿主级** | 在 Logic 里打开，看 UI / 用控制面读回 | Logic 真的接受了 |

只做解析级**不够**——读写两端可能是同一个错误假设。只做字节级也不够——改对了位置也可能写错语义。

---

## 3. 五种"假成功"（都是真实踩过的）

### 3.1 报告 OK，文件没变

```python
def _edit_pmtr(blob, edit, label, subtype=None):
    blob = bytearray(blob)      # ← 防御性拷贝
    ...                          # 改的是拷贝
    return blob                  # 调用方用的是另一个对象，从未被修改
```

**症状**：每一行都打印 `OK … 0.0 -> 0.4`，退出码 0，输出文件与输入的 **md5 完全相同，0 字节差异**。

**根因**：函数内部拷贝，调用方持有的 bytearray 从未被改。

**检出**：`md5` 对比。**光看日志永远发现不了。**

### 3.2 同一文件多处编辑，只有最后一处生效

枚举时把 plist 快照缓存下来，每次编辑都从**原始快照**开始 → 第二次编辑覆盖第一次。

**症状**：全部 `OK`，只有最后一个值在盘上。

**检出**：写入后**逐条回读**，而不是相信返回值。

**修法**：每次编辑都从当前盘上字节重新解析。

### 3.3 改对了位置，但 Logic 不看那个字段

`.cst` 槽位有两个字段（`docs/01 §3`）。只改"看起来像槽位"的那个，Logic 完全忽略。

**症状**：文件变了、解析读回也对了、Logic 里插件**一动不动**。

**检出**：只能靠宿主级验证（打开 Logic 看位置）。

**教训**：**"两个字段都写了同一个概念"是常见设计**。看到可疑的 `(n+1)*256` 这类编码，去找它的兄弟。

### 3.4 XML 改坏后，错误伪装成"找不到参数"

pad 点插错位置（插在自闭合标签的 `>` 前）→ 得到 `… /   >` → XML 非法 → 解析器返回 **0 个参数**：

```
KeyError: no XML parameter 'lateSize' (have: )
```

`have:` 是空的——这不是"参数不存在"，是"整个 XML 坏了"。

**修法**：改 XML 之后**必须重新 `parse` 一次并断言根元素还在**。

### 3.5 测试用的是副本

```python
xml_set(bytearray(raw), ...)     # ← 测的是拷贝
assert ...
```

断言永远看不到变化，测试永远通过。

**修法**：测被测对象本身；写入后从**盘上重新读**再断言。

## 4. 标准验证脚本

```python
import hashlib, subprocess, sys

def md5(path):
    return hashlib.md5(open(path, "rb").read()).hexdigest()

def diff_bytes(a, b):
    A, B = open(a, "rb").read(), open(b, "rb").read()
    assert len(A) == len(B), "size changed: %d -> %d" % (len(A), len(B))
    return sum(1 for x, y in zip(A, B) if x != y)

before = md5(SRC)

# ... 写入 ...

assert md5(SRC) == before,             "源文件被改了（不该动它）"
n = diff_bytes(SRC, OUT)
assert 0 < n <= 200,                   "差异字节数异常：%d" % n
print("差异 %d 字节" % n)

# 解析级回读
data = open(OUT, "rb").read()
for want in expected:
    got = read_value(data, want["path"])
    assert got == want["value"],      (want, got)
print("回读全部通过")
```

### 三条硬规则

1. **永远在副本上写**，源文件 `md5` 必须不变。
2. **断言文件长度**（除非你**故意**做了变长写入，并且同步修了所有长度字段）。
3. **断言差异字节数 ≤ 预期**。改 5 个参数却差了 5000 字节，说明结构动了。

## 5. 分层的"verified"含义

不要用一个 `verified` 字段表达所有事。本项目的约定：

| 层 | `verified: true` 的意思 |
|---|---|
| 字节层 | 文件确实变了，且差异字节数在预期内 |
| 解析层 | 用同一解析器读回，值等于写入值 |
| 结构层 | 结构自洽（块流走到底、长度字段一致、UUID 唯一） |
| 宿主层 | Logic 打开后 UI / 控制面确认 |

**推荐报告格式**：`{changed: true, bytes_differing: 28, reread_ok: true, logic_verified: null}` —— `null` 表示"没做宿主验证"，而不是 false。

---

## 6. 宿主级验证协议（需要人）

写完之后**不要**直接交付。按这个顺序：

1. 把产物放到**真实位置**（`~/Music/Audio Music Apps/Patches/…` 或 `~/Music/Logic/…`）
2. 在 Logic 里打开 / 加载
3. 人眼确认三件事：
   - **名字正确**（不是模板的名字）
   - **目标值正确**
   - **周围的东西没变**（其它插件、其它轨道、其它参数）
4. 立刻做一个**故意的破坏性测试**（可选但强烈建议）：只改一个值，看 Logic 是否如预期响应——确认它真的在读你写的位置
5. 关闭并**重新打开**一次（有些问题只在第二次打开才暴露）

> 第 4 条是分辨"值写对了但 Logic 不认"与"真成功"的唯一办法。

## 7. 什么时候可以不验证

只有一个例外：**自检（`--selftest`）不需要任何文件**。`logicfmt/chord.py` 和 `logicfmt/meterkey.py` 都能在无 Logic、无工程的条件下跑通纯编码/解码逻辑。

```bash
python3 logicfmt/chord.py       # chord selftest OK
python3 logicfmt/meterkey.py    # meter/key selftest OK
```

这类测试覆盖"编码/解码自洽"，**不覆盖"Logic 是否接受"**。两者都要有。
