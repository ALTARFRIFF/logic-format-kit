## 1. 工程 bundle 结构


## 2. `ProjectData` 的对象流

开头 8 字节是对象魔数：

```
23 47 c0 ab  d1 09  XX 00
                     ^^ XX = 对象类型（03 = Song，18 = 其它）
```

- 顶层只有 **3 个**这种对象（1×`03` + 2×`18`）。
- 紧接着是 `gnoS` = **`Song` 的小端字节反转**（Logic 的反转 FourCC 约定）。

### 块格式（与 `.cst` 同源）

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0` | 4 | tag（反转 FourCC：`gnoS` Song、`qeSM` MSeq、`karT` Trak、`qSvE` EvSq、`ivnE` Envi、`MneG` GenM） |
| `+28` | u32 LE | 长度 |
| `+36` | — | 载荷 |

**块总长 = 长度 + 36。**

### 两个需要注意的全局字段

| 位置 | 含义 |
|---|---|
| 全文件 `+16` | **u32 = 文件长度 − 24** |
| Song 块 `+30` | Song 载荷长度 |

任何**改变文件长度**的写入都必须同步这两个字段。

### ⚠️ 单一走链规则不够

不同 tag 的头部布局随**版本字节**变化（`qeSM` 是 `05 00`，`karT` 是 `06 00`），所以"从 +28 读长度然后跳过去"在某些 tag 上会读出 0。**可靠的定位方式是按 tag 搜索 + 按内容对齐**，不要指望线性遍历。

---

## 3. 模板法是唯一推荐路径

因为不能可靠线遍历、也不能建对象，实用做法是：

```
Logic 存一个模板工程  →  我们只改模板里已有的字段（等长）  →  Logic 打开验证
```

三个理由：

1. **Logic 会补齐自己的对象。** 一个刚建的新工程再保存，文件会**长出约 10 KB**（多 2 个 `UCuA` + 2 个 bplist）——说明对象是懒创建的。手写工程不用担心"初次打开被判损坏"，Logic 会自己补。
2. **每次保存重写全部 UUID**，所以跨文件 diff 必须掩 UUID（`CORE.md §2`）。
3. **变长风险极高**：整体错位后逐字节比会产出 16 000+ 假差异，完全没有意义。

## 4. 拍号（Time Signature）

### 记录布局：**48 字节**

记录基址 `B` = 该记录开头 `30 00 00 00` 的位置（**不是** `88` 的位置）。

| 偏移 | 类型 | 含义 |
|---|---|---|
| `B+0` | 4 | `30 00 00 00` |
| **`B+5`** | **u32 LE** | **位置 = ⌈(tick + 38400) / 256⌉** |
| **`B+11`** | **u8** | **分母的以 2 为底对数**（`2`→4，`3`→8） |
| **`B+12`** | **u8** | **分子** |
| `B+23` | u8 | 恒 `0x88`（校验用） |
| **`B+24`** | **u8** | **小节号 − 1**（缓存值，Logic 也读它） |
| `B+39` | u8 | 恒 `0x88`（校验用） |

### 定位方法

搜 4 字节 `30 00 00 00`，且 `B+23 == 0x88`、`B+39 == 0x88`。

`qSvE` 载荷内的实际排布（`_SIG-C`，载荷长 384）：

```
[0]   拍号 默认块（48B，bar = 0xf6 = 246 是末小节哨兵）
[48]  调号 默认块（32B）
[80]  拍号 事件 #1      ← 从这里起每条 48 字节
[128] 拍号 事件 #2
[176] 拍号 事件 #3
[224] 拍号 事件 #4
[272] 调号 事件 #1      ← 调号事件每条 32 字节
[304] 调号 事件 #2
[336] 调号 事件 #3
[368] 16 字节尾巴 f1 00 00 00 ff ff ff 3f …
```

**注意**：第一条拍号记录（默认块）与后续事件之间不是 48 字节，因为中间夹了 32 字节的默认调号记录。所以**不要用等步长扫描**，要用签名定位。

实测（`_SIG-C` 4 条变化，`_P2` 1 条）：

| 文件 | 拍号记录 | 含义 |
|---|---|---|
| `_P0` | 1 | 只有默认 4/4 |
| `_P2` | 2 | + 第 2 小节 3/4 |
| `_SIG-C` | 5 | + 第 2/6/10/14 小节 3/4、5/4、6/8、7/8 |

### 取整必须**向上**

位置粒度是 256 tick。向上取整后写入值落在 `[tick, tick+255]`，即**始终在目标小节内部**，Logic 打开时会吸附到该小节的小节线。
向下取整可能落到 `tick−128`（**上一小节末**），于是事件被吸附到前一小节。

`_T-MK` 的 4 条验证（tick → ⌈(tick+38400)/256⌉ → 文件里的值）：

```
第 3 小节  7680  → 46080/256 = 180.0 → 180 ✓
第 7 小节 21120  → 59520/256 = 232.5 → 233 ✓
第 11 小节 40320 → 78720/256 = 307.5 → 308 ✓
第 15 小节 55680 → 94080/256 = 367.5 → 368 ✓
```

### ★ 位置字段不能漏

只改 `B+11/B+12/B+24`、不改 `B+5` 的后果：Logic 仍按**原来的 tick** 放事件，而你又换了拍号数值，于是按新拍号重新划分小节后，事件**显示在错误的小节**上（实测：设 7/8 在第 2 小节，结果第 2 小节是 7/8 但第 5 小节变 5/4、第 12 小节变 6/4）。

公式（在 `_SIG-C` 的 4 条上验证）：

```
位置 = ceil((tick + 38400) / 256)

第 2 小节  tick 3840  → 165 = 0xa5
第 6 小节  tick 15360 → 210
第 10 小节 tick 34560 → 285
第 14 小节 tick 46080 → 330
```

> `+38400` 这个常数为什么存在**未知**，但它跨 7 个文件、13 条记录一致。照公式用。
> 精度是 **256 tick**（= 1/3.75 拍）。所以拍号位置只能落在 256 tick 的网格上——正常用（整小节）完全够。

## 5. 调号（Key Signature）

调号记录与拍号**在同一个 `qSvE` 载荷里**：拍号在前（48 B/条），调号在后（32 B/条），末尾是 16 字节尾巴 `f1 00 00 00 ff ff ff 3f …`。

### 记录布局：**32 字节**

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0` | u32 | 恒 `0x32`（= 50） |
| `+4` | u32 LE | **位置 = tick + 38400**（⚠️ **不除以 256**，与拍号不同） |
| `+12` | u32 LE | **调号编码**，见下 |
| `+23` | u8 | 恒 `0x88` |

### 调号编码（已验证 7 个文件、13 条记录）

```
code = (minor ? 0x10 : 0) | (7 + accidentals)
        ↑ bit4 = 小调        ↑ 7 = 0 个升降号；9 = 2 个升号；5 = 2 个降号
最高位 0x80000000 = "Disable ♭♯" 勾选
```

| 调 | code | 解读 |
|---|---|---|
| C major | `0x00000007` | 大调，0 升降 |
| D major | `0x00000009` | 大调，2 升 |
| E♭ major | `0x00000004` | 大调，3 降 |
| A minor | `0x00000017` | 小调（0x10），0 升降 |
| F♯ minor | `0x0000001a` | 小调，3 升 |
| B♭ major + Disable ♭♯ | `0x80000005` | 大调，2 降，高位标志 |

> **"Disable ♭♯" 是显示开关**，不影响音高。它只决定同一个音写成 `Bb` 还是 `A#`。

### 定位方法

在 `qSvE` 载荷里找满足下面两条的偏移 `i`：

```
payload[i:i+4] == 32 00 00 00  且  payload[i+23] == 0x88
```

`i` 就是记录起点。

### 写入顺序（重要）

**先写调号，再写和弦。** 因为改调号时 Logic 会问"是否把和弦轨一起变调"，这个语义在批处理里会表现成"和弦被意外改调"。反过来先写和弦再改调号，和弦可能整体移调。

## 6. 和弦记录（Chord Track）

### 和弦不是"符号"，是 **497 字节的 Region 对象**

- 每个和弦 = 一个名字字面为 **`"MIDI Region"`** 的对象，**步长精确 497 字节**。
- 记录起点 `R = 名字出现的偏移 − 54`。

### 字段

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+126` | u16 LE | **长度（tick）** |
| `+290` | u32 LE | **起点（tick）** |
| `+465` | u8 | **音程位图 低字节** |
| `+466` | u8 | **音程位图 高字节** |
| `+468` | u8 | **低音（音级 0–11）**，`0x0f` = 无 |
| `+470` | u8 | **根音（音级 0–11）**，`0x0f` = 无 |
| `+477` | u8 | `bit7` = 音阶 Auto（`0x80`） |
| `+478` | u8 | 显示缓存 `0x20 \| 根音`；`0x7f` = No Chord / 特殊 |

### ★ 位图是**相对根音**的

位图的第 n 位 = 根音上方第 n 个半音。

```
C maj   → 0x0091  = 位 0,4,7
C7      → 0x0491  = 位 0,4,7,10
C7(b9)  → 0x0493  = 位 0,1,4,7,10
C7(#9)  → 0x0499  = 位 0,3,4,7,10
C7(#11) → 0x04d1  = 位 0,4,6,7,10
C7(b13) → 0x0591  = 位 0,4,7,8,10
C7(9,#11) → 0x04d5
Cmaj7   → 0x0891  = 位 0,4,7,11
C6      → 0x0291  = 位 0,4,7,9
C5      → 0x0081  = 位 0,7
Cdim    → 0x0039  = 位 0,3,6
Caug    → 0x0111  = 位 0,4,8
D maj   → **0x0091**（与 C maj 相同，因为相对）
No Chord→ 0x0000
```

**关键推论**：因为位图相对根音，`D maj` 和 `C maj` 的 mask 完全一样，只有 `+470` 不同。

### 性质不是枚举，是位图

你看到的"Maj / Min / Sus2 / Sus4 / 5 / Aug / Dim"只是**位图的常见组合**。任意合法音程集合都能写，只要 Logic 接受（Logic 有 9 条互斥规则，见 §7）。

### 验证过的证据

- `_CHORD-A`(25) + `_CHORD-D`(15) + `_CHORD-E`(15) = **55 条记录，零例外**
- 把某条 `+465` 从 `0x91` 改成 `0x89`（去掉位 4、加上位 3）→ Logic 打开显示 **C 小和弦** ✅

### 未解的字段（不要写它们）

| 偏移 | 现象 | 建议 |
|---|---|---|
| `+479` / `+480` | 随调号/音阶/和弦变化，14 个样本**无法归纳出稳定枚举** | **不要碰**，实测它们不参与内容判定 |
| `+44` / `+395` | 每个 region 唯一的 ID | 继承，不要改 |
| `+477` 低 7 位 | 只确认 `bit7` = Auto 音阶；19 个音阶值的编码**未知** | 只用 Auto |

### 记录不能删

把某条和弦"删除"后，**记录仍然在文件里、文件反而变大**（`_CHORD-C` 与 `_CHORD-A` 的内容**逐字节相同**，25 条记录全在）。Logic 显示的是"继承上一个和弦"。

**所以"删除和弦"要用 `No Chord` 事件，不要指望删记录。**

## 7. 和弦的语义合法性（写之前必须过这一关）

Logic 的扩展音有互斥规则。写一个它不接受组合，它会在打开时**自动改写**你写的东西（实测：`13` 单独存在会被改成 `6`，必须同时带 7 度）。

| 规则 | 内容 |
|---|---|
| 五音冲突 | 有 `b5` 就不能有 `#5`，也不能有 `#11` |
| 九音冲突 | `b9` ↔ 不能有 `9`；`9` ↔ 不能有 `b9`/`#9`；`b9` 与 `#9` **可以共存** |
| 铁律 | 一旦有 `b9` 或 `#9`，永远不能有纯 `9` |
| `#5` 强绑定 | 有 `#5` ⟹ 只能是 `Aug`；非 `Aug` ⟹ 不能有 `#5` |
| Min | 不能有 `#5`、`#9` |
| Sus2 | 不能有 `b9`、`9`、`#9` |
| Sus4 | 不能有 `#9`、`#11` |
| 5 | 不能有 `#9` |
| Aug | 必须有 `#5`；不能有 `b5`、`b13` |
| Dim | 必须有 `b5`；不能有 `#5`、`#9`、`#11` |

**多扩展音可以共存**（实测 `C7(9,#11,b13)/E` 合法）。

## 8. 刻度

```
1 拍（四分音符） = 960 tick
1 小节（4/4）    = 3840 tick
小节 1 起点      = tick 0
```

分数长度合法（1/4 小节 = 960 tick）。

> ⚠️ 拍号一旦在文件里变化，**小节 → tick 的换算就要按变化后的拍号分段累加**。写第二个事件之前先把前面的拍号变化算进去，否则位置全错。

## 9. 标准工作流（推荐照抄）

```python
# 1) 拿模板，量一下有多少槽位
recs = chord.find_records(data)          # 497 步长扫描，返回每条记录起点
slots = len(recs)
print("本模板 %d 个和弦槽位" % slots)

# 2) 逐条就地改写（等长，不动文件长度）
for i, spec in enumerate(chords):
    chord.write_record(data, recs[i], start=..., length=...,
                       root=..., ivs=..., bass=...)

# 3) 多余的槽位写成 No Chord（否则会显示模板里的旧和弦）
for i in range(len(chords), slots):
    chord.write_no_chord(data, recs[i], start=i * 3840, length=3840)

# 4) 断言文件长度没变
assert len(data) == len_before

# 5) 回读
for rec in chord.read_records(data):
    print(rec["start"], rec["length"], chord.describe(rec))
```

拍号/调号同理（见 `logicfmt/meterkey.py`）。

> **槽位不够怎么办**：现在**不支持真插入**。做法是让用户在 Logic 里再存一个"和弦更多"的模板。这比实现插入便宜一个数量级，而且不会有静默失败风险。

# 附录 A · 通道条与发送（`logicfmt/mixer.py`）

> 全部偏移都是 **chunk 载荷相对偏移**（载荷 = chunk 起点 + 36）。以下每一项都在
> `templates/` 里的 6 个工程上实测过，`logicfmt/mixer.py` 自带 39 条断言。

## A.1 怎么找到一条轨

排列区的一条轨 = 一个 `OCuA` 头（长度 **201 / 209 / 237 / 249**，载荷 +97 起是名字），
紧跟它自己的 `UCuA(76)`（**每条 Send 一个**）和 `UCuA(303)/UCuA(348)`（通道条覆盖）。

环境区的 `Input 1` / `Aux 1` / `Output 1` / `Bus 1` 对象形状相同但**不是**排列轨，
按名字前缀排除。**Aux 与 Stack 主轨是 `ivnE(467)`，不是 `OCuA`。**

## A.2 推子：`OCuA` 载荷 +85（u8）

```
byte = clamp( int(90 * 10 ** (dB / 40)), 0, 127 )     # -∞ → 0，向下取整
dB   = 40 * log10(byte / 90)
```

十点标定：0 dB→90、+6→127、−3→75、−6→63、−12→45、−20→28、−30→16、−40→9、−60→2、−∞→0。
取整是**向下截断**而不是四舍五入（−3 dB 的理想值是 75.71，存 75）。
−40 dB 以下一格约 3 dB，所以低端只能精确到格。

## A.3 其余单字节字段

| 偏移 | 含义 | 取值 |
|---|---|---|
| **+89** | 声像 | 0 = 最左，64 = 居中，127 = 最右（`byte = pan + 64`，pan 范围 −64..+63） |
| **+88** bit0 | 独奏 | 1 = 开。**多条可同时为 1** |
| **+90** bit0 | 静音 | 1 = 开 |
| **+90** bit1 | 「通道条偏离默认」 | 开关状态未定，**写入时不要动它** |
| **+92** | 输出目的地 | `0` = Stereo Out，`0xFF` = No Output，否则 **= bus + 1** |

输出实测：Bus 3→`04`、Bus 5→`06`、Bus 7→`08`、Bus 9→`0a`。

> **独奏不写静音**：某轨独奏时，其他轨的 `+90` bit0 仍为 0。Logic 只在播放时实时把
> 其他轨显示为变暗，不落盘。

## A.4 Send：每条 Send 是一个 `UCuA(76)`

| 偏移 | 含义 |
|---|---|
| **+16** | `01` = Post；`00` = 另一种（唯一一条 Pre 样本，语义待定） |
| **+17** | 电平字节，**与推子同一套 0..127 律** |
| **+20** | 目的地 = **bus + 3**（Bus 3→`06`、Bus 5→`08`、Bus 7→`0a`） |
| **+27** | 电平镜像（末字节同 +17）。**只写 +27 这一个字节**，`+24..+26` 是随机片段 |
| +60..+75 | 16 字节 UUID，每条不同 |

Send 电平与推子**共用同一张表**：0 dB→90、−6→63、−12→45、−20→28、−30→16、−40→9、−60→2、−∞→0。

**注意**：输出目的地用 `bus + 1`，Send 目的地用 `bus + 3` —— 两个字段基数不同，
不要混用。

## A.5 已知缺口

| 项 | 状态 |
|---|---|
| Pre/Post 的写入 | **未定性**。唯一一条 Pre 样本 `+16 = 00` 且 `+20 = 01`，不符合 `bus+3` |
| 新建 Send（插入新的 `UCuA(76)`） | 未实现，目前只能改已有 Send |
| Aux / Stack 主轨（`ivnE(467)`） | 已定位对象，字段未解 |
| Marker / Tempo / 自动化 / MIDI 区域 | 已定位容器（`rpyH` 是自动化轨），字段未解 |

## 附录 B：Aux / Summing Stack / Folder Stack 主轨 = `ivnE(467)`

三类通道的「主轨对象」是同一个块类型 `ivnE`、同一个长度 **467**，靠一个字节区分。

### 读取（13 个已知样本零例外）

| payload 偏移 | Aux | Summing | Folder | 用途 |
|---|---|---|---|---|
| **+155** | `0x05` | **`0x10`** | **`0x14`** | **三向判别符，唯一可靠** |
| +45 | `01` | `03` | `01` | 只有 Summing 是 `03` |
| +148 | `24` | `24` | **`23`** | Folder 独有 |
| +86 | `42` | `40` | `40` | Aux=`42`，两种 Stack=`40` |
| +160 | 名字（ASCII，`SUM1` / `FLD1` / `AUX3`） | | | |
| +16 | 通道序号（同文件内按 `0x04` 递增） | | | |

**不要用 `ivnE(471)`**：那是 Environment 里每条通道条都有的对象，`+155` 恰好也是 `0x10`，误判会把所有轨都读成 Summing。

## 附录 C：Stack 的成员关系（已解）

两类 Stack 的成员关系用**完全不同的机制**表达，这是之前一直找不到「父子链接」的原因。

### Folder Stack：一个字节

音频轨通道条（`OCuA` 201/237/241）载荷 **`+110 = 0x01`** 即「我是某个 Folder Stack 的子轨」。

38 个轨道样本、零误报：
- `_SKELETON` Audio 3 / Audio 4 = `01`（FLD1 的两个子轨），其余 6 条 `00`
- `_SKELETON2` Audio 3 / Audio 4 = `01`，其余 `00`
- `_STACK` Audio 5 / Audio 6 = `01`，其余 `00`
- `_P1`、`_MIX-A` 全部 `00`

**没有父对象指针**——Folder Stack 不记录「谁是我的父」，子轨只声明「我在某个折叠里」。父是谁由折叠范围（排列顺序）决定。

### Summing Stack：只有输出路由

子轨 `+92` 指向 Stack 那条 Aux 的 bus（`bus + 1`），**没有额外标志位**：
- `_SKELETON` Audio 1 / 2 → `0x02` = Bus 1 = SUM1
- `_STACK` Audio 3 / 4 → `0x02` = Bus 1 = SUM1
- `_SKELETON` Audio 5 → `0x03` = Bus 2 = AUX2

### 代码

```python
import project as P
for t in P.audio_tracks(data):
    print(t["name"], t["out"], t["in_folder"])   # stereo / bus1 / none, True/False
data = P.set_folder_member(data, start, True)     # 改 1 字节，等长
```

### 仍未打通：从零「新建」一个 Stack

成员关系已可写，缺口只剩**主轨对象本身**：需要同时造出 `karT` + `qSvE` + `qeSM(309)` + `ivnE(467)` + 通道条，并让排列顺序把它排在子轨之前。这一步未验证，所以目前的做法仍然是「模板里已有 Stack，改名字/类型/成员」。

## 附录 D：真插入（真正让文件变长）

`chord` / `meterkey` 原先只能「就地覆盖已有槽位」。现在可以真正插入记录：

```python
ch   = P.chunks(data)
head = data[:P.HEADER]
ch[i] = P.insert_in_payload(ch[i], off, blob)   # 载荷变长，块 +28 自动重算
out   = P.seal(ch, head)                         # 重算文件头 +16 的总长度
```

`seal()` 是**必须的**——它把 `header +16` 写成 `len(body)`。少了这一步 Logic 会**静默打不开**。

自检（`project.py selftest` 的 `insert selftest`，6 项）实测：往 `_SIG-C` 的 `qSvE` 里插入一条 48 字节拍号记录后

|---|---|
| 文件大小 | 118,534 → 118,582（正好 +48） |
| 头部 `+16` | 自动等于 `len − 24` |
| 重新解析块数 | 不变，只有 `qSvE` 长了 48 |
| 原有拍号记录 | 一条没动 |
| 新增记录 | 6/8 @ 第 20 小节，被 `meter_blocks` 正确读出 |
| 后面的调号记录 | 整体后移 48，代码与位置都正确 |

**边界**：目前验证的是「往已有 `qSvE` 里插入记录」。往**对象流**里插入整块（新建块类型）走的是另一条路径（`rebuild` + 手工排序），尚未验证。

# 附录 E · 速度（BPM）与任意小节的速度变化

属于自己的一个 `qSvE` 块（**与拍号/调号那个 `qSvE` 是不同的块**）。载荷：

```
[默认速度 32 字节][速度事件 64 字节 × N][16 字节尾巴]
32 + 64*N + 16 = 载荷长度
```

默认块与事件共用的头 32 字节：

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0` | u32 | `0x60`（96） |
| `+4` | u32 | **位置 = tick + 38400** |
| `+12` | u32 | `0x7f`（127） |
| `+16` | u32 | **BPM × 10000**（不是 float32） |

事件的第 33..63 字节是 Logic 自己的附加字段，写新事件时**从现有事件克隆**（`templates/donors/tempo_event.bin`）。

参考实现：`logicfmt/tempo.py`（`find_tempo_chunk` / `tempo_records` / `apply_tempo_map` / `tempo_at`），
`python3 -m logicfmt.tempo` 自检 **17 passed**。

**实测验收**：以 `_TL-BASE` 为底写入 bar2=100、bar5=150，Logic 的 Tempo List 读回

```
bar 1 = 120   bar 2 = 100   bar 5 = 150
```

与写入值完全一致（`logic_tempo_events` 返回 `verified: true`）。

## 附录 F · Marker 位置（✅ 已用 Logic 验收）

**Marker 位置不在 `gnoS`，也不在 `qSxT`（`qSxT` 只存名字的 RTF 文本）。它在一个独立的 `qSvE` 里。**

```
marker 容器（一个 qSvE）= N × 48 字节记录 + 16 字节尾巴
```

| 记录偏移 | 类型 | 含义 |
|---|---|---|
| `+0` | u32 | `0x12` 类型标记 |
| **`+5`** | **u32 LE** | **位置 = (tick + 38400) / 256**（与拍号事件同一条公式）|
| `+16` | u8 | 序号缓存 = `(index + 1) * 4`（**是 `+16` 不是 `+15`**）|
| `+23` | u8 | `0x88` 记录签名（定位用）|
| `+28` | u32 | `1` |
| `+39` | u8 | `0x88` 第二个签名 |

尾巴 16 字节 = `f1 00 00 00 ff ff ff 3f 00 00 00 00 00 00 00 00`。

**验收**（`_T-MARK.logicx` = `_TL-MARK` 用本模块把三个 marker 移到 bar 3 / 7 / 12 并追加一个）：

```
写入: (0,3) (1,7) (2,12) (3,20)
Logic: Intro @ 3 1 1 1 / Verse @ 7 1 1 1 / Chorus @ 12 1 1 1     ← 三条位置全对，名字跟着走
```

**移动 = ✅**（等长改写，只动 4 个字节）。
### 新增 marker：Logic 自己的增量已拿到，但仍差一层登记（🟡 未解）

让 **Logic 自己**加一个 marker（`_TL-MARK2` 3 个 → `_H-MARK` 4 个，bar 20，名字 `Marker 4`），逐块比对得到完整增量：

| 变化 | 内容 | 能否离线复刻 |
|---|---|---|
| `qSvE:160` → `qSvE:208` | marker 容器 **+48 字节**（一条记录） | ✅ 能做 |
| **`qSxT:483` +1** | **marker 名字是独立对象**（RTF 文本） | ✅ 能做 |
| `gnoS` +40 | 一条登记记录 | ❌ 未解 |
| `qeSM:307` −1 / `qeSM:305` +1 | 登记对象改写 | ❌ 未解 |

名字对象的结构（`qSxT`，483 字节）：

```
+0  u32 = 载荷长度（与 +20 重复）
+16 0x62 'b'
+20 u32 = 载荷长度
+24 u32 = 0x13
…   空格填充
{\rtf1\ansi\ansicpg936…\f0\fs24 \cf2 <名字>}
```

**实测结果**：只做前两项（记录 + 名字对象）时，Logic 仍显示 **3 个 marker**，而且第 3 个的名字被错配成新加的名字（`Chorus` → `Outro`）—— 说明 marker 与名字之间还有一层登记表，光加数据不登记反而更糟。

`gnoS` / `qeSM` 这两处过去多次证明「照抄即损坏或崩溃」（`_F6`/`_F7`/`_G19`），所以 `markers.add()` **默认 raise `NotImplementedError`**，只有显式 `allow_incomplete=True` 才执行，且文档写明产物不可用。

**所以 marker 的现状是：移动 ✅ 已验证；新增 🟡 增量已知、差一层登记。** 实践路径：用 Logic 建一次 marker，之后用 `set_position` 任意移动。

## 附录 G · 自动化曲线（✅ 已用 Logic 验收）

曲线是一个**大 `qSvE`**（`_TL-AUTO` 24,608 B / `_TL-AUTO2` 23,728 B —— 长度随曲线形状变，说明是按段细分的采样折线）。

**记录 = 16 字节，`+0` 恒为 `0x50`，步长严格 16：**

| 偏移 | 观测 |
|---|---|
| `+0` | u32 `0x50`（记录标记）|
| `+4` | u32 LE 低字节，**实测 = tick + 38400**（`96 00 00 00` → tick 0；`96 00 00 0f` → tick 15，采样步长 15 tick）|
| `+8..+10` | 3 字节，含义未定（写曲线时保持原值）|
| **`+11`** | **u8 音量字节 —— 与推子同一张表 `b = 90·10^(dB/40)`。这就是曲线的值** |
| `+12..+15` | `07 00 00 00` / `07 00 00 40` |

**2. 写折线**：同文件用 `set_curve([(1,0),(5,-12)])` 写一条每小节降 3 dB 的斜坡

## 附录 G · MIDI 区域（音符）

一个 MIDI 区域的内容存放在**独立的 `qSvE` 块**里（记谱容器）：

```
payload = [事件记录 ...][16 字节尾巴]
尾巴   = f1 00 00 00 ff ff ff 3f + 8 x 00
```

### G.1 音符记录（Logic 手绘区域：32 字节）

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0`  | u32 | `0x90`（记录类型：音符）|
| `+4`  | u32 | `tick（相对区域起点）+ 38400` |
| `+11` | u8  | **力度 velocity** 1..127 |
| `+12` | u8  | **音高 pitch**（MIDI 号，60 = C3）|
| `+23` | u8  | `0x89`（记录尾签名）|
| `+28` | u32 | **长度**（tick，960 = 一拍）|

`+10 = 0x41`、`+15`、`+16 = 0x40` 在样本内恒定或语义未定；写入时保持原值。

### G.2 控制器记录（48 字节）

以 `0xb0` 开头，与音符共用同一套位置/数值字段：

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0`  | u8  | `0xb0`（记录类型：控制器）|
| `+4`  | u32 | **位置** = tick + 38400 |
| `+11` | u8  | **数值** 0..127 |
| `+12` | u8  | **控制器号**（64 = 延音踏板，11 = 表情，1 = 调制轮）|

**验收**：把 bar 11 那条 `Control 64 = 0` 的 `+11` 改成 100、文件只差 1 个字节，
Logic 的 Event List 读回 `Control 64 = Sust ain` 的值 **100**。

同一个容器里音符是 **64 字节**、控制器是 **48 字节**（录制产生的区域），
手绘区域里音符是 **32 字节**。所以音符记录长度随上下文变化：
`stride()` 只在全等步长时给值，`append_note()` / `append_cc()` 在步长不符时拒绝写入。
