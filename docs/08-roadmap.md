# 08 · 未完成项与卡点（可发布能力的边界）

截至 2026-10-22，`logicfmt` 覆盖的能力见 `CORE.md` 矩阵。本文只记**还没走通的三项**，
每项都写清：卡在哪、证据在哪、什么能解开它。目的是让接手的人（或下一轮）不需要重做
已经做过的实验。

## 一句话总览

三项未完成里，**Marker 新增**与**新建 Send** 撞的是**同一个根因**：Logic 的**对象 id 图**。
`PvWr` / `FrAr` 两个插件容器则是**缺样本**，本机没有办法推进。

| 项 | 状态 | 根因 | 解开条件 |
|---|---|---|---|
| Marker 新增 | 🟡 读/改/移动 ✅，新增 ❌ | 保存时的 id 重编号语义 | 搞清 id 分配/校验规则 |
| 新建 Send | 🟡 改已有 ✅，新建 ❌ | 同上（Send 记录要指向 Aux 的对象 id） | 同上 |
| `PvWr` / `FrAr` 容器 | ⚠️ 只能报 magic、拒写 | 本机无样本 | 一个含 Polyverse / Slate 插件状态的工程或 `.aupreset` |

## 1. Marker 新增

**已经有的**（可直接复用，见 findings §64 的干净真值对 `PA`→`PB`）：

* 真正的 Marker 列表是 **`qSvE:64`**（16 B 头 + 48 B 记录 + 16 B 尾符），
  不是之前误认的 `qSvE:80`（那个容器在 0 Marker 时就已经存在且逐字节相同）。
* 新建一个 Marker 的完整交付物 = **3 块对象**（`qSvE:64` + `qeSM:305` + `karT:0`，插在
  第 406 块处）+ **2 块 `qSxT`**（99 B 索引、483 B RTF，追加在文件末尾）+ **`gnoS` +160 B**
  （四段登记行 + `+222`/`+228` 两个计数各 +1）。五块原始字节已存成
  `templates/donors/marker_delivery.bin`（1,131 B）。
* 记录结构：48 字节，位置在记录 `+5`；移动/改名/删除都已在真实工程里验证。

**卡点**：新对象的 **id 分配**与 **`gnoS` 登记行的 id 字段**。两种类型的 id 在块头里
位置不同（`qeSM`/`karT` 用 `hdr[2]>>16`，`qSvE` 用 `hdr[3]>>16`），而 `gnoS` 行里的
数字（22/32/25/30…）与这两个 id 对不上，说明还有一层“登记序号”没解开。
直接照抄 donor 的 id 会与目标工程已有对象撞号。

**解开条件**：搞清 `gnoS` 行的字段语义（哪一段是对象 id、哪一段是类型/序号）。

## 2. 新建 Send

**已经有的**：改已有 Send 的电平/目的地（`mixer.py`）、完整真值与增量（findings §63）：

* 通道条侧：所有 `payload[4]==0x40` 的 `OCuA:237` 升级成 241 —— `+026`/`+028` 各 +1，
  `+136` 插 `01 00 00 00`（三处，逐字节确认）。
* Send 本体：一条 `UCuA:76`，插在拥有它的那条轨的条组末尾。
* Aux 侧：**不新增通道条块**，只加 5 个对象块（`ivnE:469`+`karT:58`+`karT:0`+`qeSM:309`+`qSvE:16`），
  外加 `qSvE` 值表 +80、`gnoS` +80。

**卡点**：`UCuA:76` 要指向 Aux 的对象，克隆进来的 Aux 块带着 donor 的 id；按 Marker 那边的
教训，id 与父引用必须成组一致，否则 Logic 静默丢弃。

## 3. `PvWr` / `FrAr`

* `PvWr`（44 B，Polyverse）：`~/Library/Audio/Presets/Polyverse Music/{Supermodal,Wider}` 目录为空，
  本机没有任何 `.aupreset`；`Filterverse.component` 是注册的（`aumf` / `PLVm` / `PvFv`），
  但 MCU 插件浏览器走完整目录（100+ 项）也不命中它的显示名，无法让 Logic 实例化它。
* `FrAr`（2522 B，Slate Digital）：同样没有样本工程。
* 目前行为是**诚实降级**：`classinfo.describe_blob()` 报出 magic 与 `family="unknown"`，拒写；
  自检用合成样本锁住这个行为（`PvWr` 44 B / `FrAr` 2522 B 必须判 unknown）。

**解开条件**：一个含这两个插件状态的工程（或它们导出的 `.aupreset`）。

## 4. 建议的下一步（按性价比排序）

1. **id 图**：拿一份“只做一次保存、别的什么都没改”的真值对（同一工程，⌘S 两次），
   逐条列出所有带 id 的块、以及载荷内引用该 id 的位置，写成一个“id ↔ 引用”检查器。
   有了它，Marker 与 Send 两项可以一起收口。
2. **Send**：在拿到 id 规则之后，用 §63 的增量与 §63.2 的三处改写直接实现。
3. **插件容器**：等样本；期间不再投入。

## 5. 不要重做的实验

* 往 `qSvE` 里复制 48 字节记录 + 复制 `qSxT` → Marker 不增加（§50.4）。
* 补 `gnoS` 的 40/80 字节登记行 → Marker 不增加（`S1` 去掉 gnoS 增量仍读出 1 个，§50.8）。
* 改容器块头的 `+8`/容量字段 → 数量不增（§57–§60）。
* 单变量试遍“名字对象 / 计数 / 位置 / 容器块头” → 全部归档在 §57–§61。
