
### §50.6 第二个 Marker 的增量（把“一次性”和“每个”分开）

再在 `_M1`（已有 1 个 Marker）里于第 5 小节建第 2 个 Marker，⌘S 得 `S2M`
（136,385 B / 465 块）。`S1`(1 个) → `S2M`(2 个) 的差异：

```
gnoS:Song  21,238 → 21,278   (+40)
qSvE:EvSq      64 → 112      (+48)
末尾新增     qSxT:qSxT 483
```

所以：

| 每次新建都要 | 只在“工程的第一个 Marker”时做 |
|---|---|
| `qSvE` 追加 48 B 记录 | 末尾那条 `qSxT:qSxT` **99 B** 的索引块 |
| 末尾追加一条 `qSxT:qSxT` 483 B（RTF） | gnoS 的第一份 +40（见下） |
| gnoS **+40** | — |

gnoS 的这 40 字节由两段插入组成（S1→S2M 实测，其余差异是 UUID 抖动）：

```
+24 @14108 : 20 00 00 00 | 08 00 00 00 | <16B uuid>
+16 @21156 : 20 00 00 00 | 04 00 00 00        ← 只有 16 B，uuid 尾部落进后面的已有字节
```

另外 gnoS 里有两处单字节随 Marker 数变化：`+465` 与 `+472`（1 个 Marker 时 `0x88`，
2 个时 `0xd2` = 210）。它们看着像“Marker 表的下一个可用偏移”，不是简单计数 ——
**这正是最后一块没定论的地方**（§50.3 说的那 8 字节差额）。

### §50.7 结论（本轮）

Marker 新建 = **4 段写入**（48B 记录 + 483B qSxT + 24B gnoS 行 + 16B gnoS 行 + 2 字节位移字段），
第一枚 Marker 再加一段 99B 索引块。真值成对存在 `_probes/_M0`→`_M1`、`_M1`→`_M2`… 这条链上，
下一轮按 donor 法把 4 段克隆进去，用 `S0 + 1 Marker == S1` 做验收即可。
目前的实现（`logicfmt/markers.py`）仍只做读/移动/改名，新增保持 🟡。
